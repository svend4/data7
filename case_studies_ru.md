## Кейс 2: Биология (Экспериментальная диссертация)

### Контекст

**Тема:** "Влияние микроРНК на регуляцию метаболизма в клетках печени"

**Аспирант:** Дмитрий, 4-й год PhD
**Проблема:** Много экспериментальных глав, неясно, в каком порядке их располагать

### Исходная проблема

У Дмитрия 3 типа экспериментов:
- In vitro (культуры клеток)
- In vivo (мыши)
- Биоинформатический анализ

Каждый эксперимент породил отдельную главу. Неясно: начать с простого (in vitro) или с анализа данных?

### Результат оптимизации

Алгоритм подтвердил **естественную последовательность биологического исследования**:

```
Биоинформатика (гипотезы)
    ↓
In vitro (валидация)
    ↓
Механизм (понимание)
    ↓
In vivo (физиологическая релевантность)
    ↓
Клиническая значимость
```

**Почему такой порядок оптимален:**

1. **От данных к гипотезам** (биоинформатика)
   - Широкий взгляд, множество кандидатов
   - Низкая когнитивная нагрузка (анализ данных)

2. **От гипотез к проверке** (in vitro)
   - Контролируемые условия
   - Быстрая проверка предсказаний

3. **От феномена к механизму**
   - Углубление понимания
   - Естественное любопытство читателя ("почему?")

4. **От механизма к организму** (in vivo)
   - Проверка в сложной системе
   - Физиологическая релевантность

5. **От науки к медицине**
   - Практическое применение
   - Мотивирует все предыдущее

**Альтернативный порядок (хуже):**
Начать с in vivo → феномен непонятен, нет контекста.

```python
# Настраиваем веса: temporal важнее для исторической диссертации
```

### Результат

Алгоритм подтвердил **хронологический порядок** как оптимальный для этой диссертации.

**Почему:**
- Минимальная temporal distance (эпохи идут последовательно)
- Естественная причинно-следственная связь (события X века влияют на XI)
- Читатель не прыгает во времени

**Альтернативные структуры (проверены):**

### Исключение: Comparative chapter в конце

Сравнительная глава (epoch=2) идет после всех исторических глав — это правильно:
- Требует знания всего материала
- Аналитический, а не повествовательный характер
- Современный взгляд на прошлое

### Вывод для исторических диссертаций

- **Хронологический порядок оптимален** для большинства случаев
- Увеличьте вес `temporal` до 0.4-0.5
- Аналитические главы (сравнение, теория) — в конец

## Кейс 4: Междисциплинарная диссертация

### Контекст

**Аспирант:** Игорь, 4-й год PhD
**Проблема:** Диссертация на стыке CS и истории. Разные научные руководители требуют разную структуру.

### Конфликтующие требования

**Научрук 1 (историк):**
"Начните с исторического контекста! Без понимания эпохи нельзя интерпретировать тексты."

**Научрук 2 (компьютерщик):**
"Начните с методов! Это PhD по CS, историю можно в конец."

### Два варианта структуры

**Вариант A (история первая):**
```
1. Введение
2. Исторический контекст (XVIII век)
3. Корпус текстов и их особенности
4. Обзор литературы (история)
5. Основы NLP
6. Обзор литературы (ML)
7. Предлагаемые методы
8. Эксперименты
9. Историческая интерпретация
10. Заключение
```

**Вариант B (CS первый):**
```
1. Введение
2. Основы NLP
3. Обзор литературы (ML)

5. Корпус текстов
6. Эксперименты
7. Исторический контекст
8. Историческая интерпретация
9. Заключение
```

### Применение multi-objective оптимизации

```python
from advanced_methods import MultiObjectiveOptimizer

# Создаем главы
chapters = [...]  # 10 глав

# Многокритериальная оптимизация
mo_optimizer = MultiObjectiveOptimizer(base_optimizer)

# Оптимизируем сразу:
# 1. Когнитивную стоимость
# 2. Удовлетворение историка (история раньше)
# 3. Удовлетворение компьютерщика (методы раньше)

pareto_front = mo_optimizer.nsga2_optimize(population_size=200, generations=500)

# Анализируем компромиссные решения
for i, solution in enumerate(pareto_front[:3]):
    print(f"\nРешение {i+1}:")

    # Позиция исторического контекста
    hist_pos = solution.index("historical_context")
    print(f"  История на позиции: {hist_pos}")

    # Позиция методов
    methods_pos = solution.index("methods")
    print(f"  Методы на позиции: {methods_pos}")

    metrics = mo_optimizer.compute_objectives(solution)
    print(f"  Когнитивная стоимость: {metrics['cognitive_cost']:.2f}")
```

### Результат: Компромиссная структура

**Оптимальное решение (из Парето-фронта):**

```
1. Введение
2. Обзор задачи (краткий контекст + краткие методы)  ← НОВАЯ ГЛАВА!
3. Исторический контекст (детально)
4. Корпус текстов и их особенности
5. Основы NLP и обзор литературы
6. Предлагаемые методы
7. Эксперименты
8. Результаты: количественный анализ
9. Результаты: историческая интерпретация
10. Заключение
```

**Ключевое решение:** Добавлена **обзорная глава #2**, которая:
- Дает общее представление о задаче
- Кратко вводит и историю, и методы
- Позволяет читателю понять "зачем всё это"
- Удовлетворяет обоих научруков

**Метрики:**
- Вариант A (история первая): cost = 6.2
- Вариант B (CS первый): cost = 5.8
- **Компромисс (с обзорной главой): cost = 4.1** ✅

## Кейс 5: Адаптивная оптимизация в процессе написания

### Контекст

**Тема:** "Разработка квантового алгоритма для оптимизации портфелей"

**Аспирант:** Мария, 3-й год PhD

### Исходный план

Мария начала с оптимизированной структуры:

```
1. Введение ✅ написано
2. Основы квантовых вычислений ✅ написано
```

### Проблема в процессе

После написания главы 3 Мария обнаружила:
- Переход 2→3 оказался очень сложным (много новых концепций)
- Переход 3→4 будет легким (мало общего между квантовыми алгоритмами и финансами)

### Применение adaptive learning

```python
from advanced_methods import AdaptiveLearningOptimizer

# Создаем адаптивный оптимизатор
adaptive = AdaptiveLearningOptimizer(base_optimizer)

# Записываем реальный опыт написания
adaptive.record_writing_session(
    from_chapter="quantum_basics",
    to_chapter="quantum_optimization",
    actual_difficulty=0.85  # очень сложно!
)

adaptive.record_writing_session(
    from_chapter="quantum_optimization",
    to_chapter="portfolio_theory",
    actual_difficulty=0.3  # легко (разные темы, нет пересечения)
)

# Система обновляет оценки дистанций
# Теперь дистанция 2→3 увеличилась, 3→4 уменьшилась

# Переоптимизируем для оставшихся глав
remaining_chapters = ["portfolio_theory", "proposed_algorithm",
                     "implementation", "experiments", "comparison", "conclusion"]

new_plan = adaptive.reoptimize(remaining_chapters)
```

### Новый оптимальный план

```
1. Введение ✅
2. Основы квантовых вычислений ✅
3. Теория портфелей ← ПЕРЕМЕСТИЛИ РАНЬШЕ!

7. Эксперименты

```

**Изменение:** Глава о портфелях перемещена раньше!

**Почему это лучше:**
- **Разгрузка после сложной главы 2**
  - После тяжелой квантовой механики идет легкая финансовая теория
  - Читатель "отдыхает"

- **Мотивация для главы 4**
  - Теперь, изучая квантовые алгоритмы, читатель знает, зачем (для портфелей)
  - Легче связать абстрактные алгоритмы с конкретной задачей

- **Лучшая интеграция в главе 5**
  - Предлагаемый алгоритм соединяет квантовую механику И финансы
  - Обе темы уже введены

```python
# Мария продолжает писать и записывать опыт
for session in writing_sessions:
```

## Выводы и паттерны

### Общие паттерны из всех кейсов

#### 1. Естественная последовательность обычно оптимальна

**Для экспериментальных наук:**
```
Гипотеза → Эксперимент → Результат → Интерпретация
```

**Для теоретических наук:**
```
Проблема → Существующие подходы → Новый подход → Следствия
```

**Для исторических наук:**
```
Хронологический порядок (с аналитическими главами в конце)
```

#### 2. Контекст должен идти рано

Все успешные структуры имеют **контекстную главу в начале**:
- Медицинский контекст (Кейс 1)
- Биологические основы (Кейс 2)
- Историография (Кейс 3)
- Обзор задачи (Кейс 4)

**Почему:** Читатель должен понимать "зачем это нужно" до изучения "как это сделано".

#### 3. Переходные главы помогают

Междисциплинарные диссертации выигрывают от **интегрирующих глав**:
- Объединяют разные темы
- Снижают когнитивную нагрузку
- Удовлетворяют разные аудитории

#### 4. Оптимизация особенно важна для > 8 глав

```
Количество глав  | Важность оптимизации
-----------------|---------------------
< 5              | Низкая (структура очевидна)
5-8              | Средняя (несколько вариантов)
9-15             | Высокая (много комбинаций)
> 15             | Критичная (экспоненциальный рост)
```

#### 5. Адаптация полезна после 30-50% написания

**Оптимальный момент для переоптимизации:**
- У вас есть реальные тексты для ML-анализа
- Вы знаете реальную сложность переходов
- Еще можно изменить порядок оставшихся глав
